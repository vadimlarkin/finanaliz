# Issue tracker: Local Markdown

Для этого проекта выбран локальный трекер: исходная папка не имела Git-репозитория и удалённого адреса. Навыки планирования работают с файлами проекта.

## Размещение

- Одна функция или изменение: `.scratch/<feature-slug>/`.
- Спецификация: `.scratch/<feature-slug>/spec.md`.
- Одна задача на файл: `.scratch/<feature-slug>/issues/<NN>-<slug>.md`, начиная с `01`, сначала зависимости.
- Состояние задачи: строка `Status:` в начале файла.
- Зависимости: строка `Blocked by:` с номерами или относительными ссылками; `None`, если зависимостей нет.
- Обсуждение: раздел `## Comments` в конце файла.

## Операции

«Опубликовать в трекере» означает создать соответствующий локальный файл. «Получить задачу» означает прочитать файл по указанному пути. При неизвестном номере найди его в `.scratch/` и проверь название; не угадывай.

Работай над задачами, все зависимости которых завершены. Завершённая задача имеет `Status: completed`; фиксируй результат и выполненные проверки в её файле. При создании спецификации указывай `Status: ready-for-agent` после заголовка.

## Состояния

Навык `triage` не установлен. Для совместимости с `to-spec` и `to-tickets` используй следующие состояния прямо в файлах:

- `needs-triage` — требуется оценка задачи.
- `needs-info` — не хватает конкретных данных.
- `ready-for-agent` — задача определена и готова к выполнению агентом.
- `ready-for-human` — требуется действие человека.
- `wontfix` — принято решение не выполнять.
- `in-progress` — выполняется.
- `completed` — результат и необходимые проверки готовы.

Внешний трекер подключай, когда пользователь укажет его. До этого спецификации и задачи сохраняй в проекте.
