# Получение исходников с общего диска

Поручение пользователя от 05.11.2026 передано из чата «Найти общий диск вБетон». Цель: пользователь указывает папку, навык самостоятельно получает исходные документы перед проверкой комплектности и локальным разбором. Исходная проверенная инструкция находится в проекте Yandex Disk MCP, документ `docs/skill-integration-handoff.md`.

## Требования

1. Принимать относительный путь, полный путь настроенного общего диска и обычную ссылку на его папку. При неоднозначном названии уточнять выбор; соседние сделки и весь диск по умолчанию не обходить.
2. Получать выбранный комплект со всеми страницами списка и вложенными папками. Сохранять русские имена, структуру, архивы и комплекты подписей.
3. Реально скачивать байты и проверять размер и доступные контрольные суммы. Метаданные и выдача URL сами по себе не означают получение файла.
4. Сохранять происхождение, remote path, resource_id и modified при наличии, размер, удалённые и локальные хеши, локальный путь и результат каждого получения.
5. Продолжать получение после обрыва без потери проверенных файлов. При изменении исходника сохранять новую версию и историю; не смешивать прежний комплект с текущим.
6. Различать пустую папку, отсутствие ресурса, ошибки пути, авторизации, доступа, блокировки, ограничения частоты, недоступность сервиса и неполное скачивание.
7. Использовать только чтение. Токен получать из отдельной записи Keychain в память; токены и временные ссылки не сохранять в документах, реестрах и журналах.
8. Сохранить финансовые предпосылки, корпоративный обязательный минимум, порядок ИП, требования к ОСВ, выпискам и локальному PDF/OCR. Неполученный документ остаётся явным пробелом.
9. Не изменять и не выполнять восемь ранее согласованных расчётных задач. Установку, выпуск, проверку других Mac и практическую финансовую приёмку учитывать отдельно.

## Реализация

В основной инструкции навыка добавлен ранний переход к [порядку получения](../skills/borrower-financial-analysis/references/yandex-disk-sources.md). Путь либо полученный локальный комплект с реестром передаётся аналитику. Входом финансового разбора являются актуальные проверенные записи текущего реестра; ошибки и ограничения передаются вместе с ними.

Подключённый MCP используется для проверки диска и обычного чтения. Его текущие инструменты представляют часть метаданных текстом с округлённым размером. Для точной сверки, воспроизводимого пакетного получения и продолжения добавлен [локальный клиент](../skills/borrower-financial-analysis/scripts/fetch_yandex_disk.py) на стандартной библиотеке Python. Он выполняет GET только к ресурсам общего диска и временным HTTPS-ссылкам скачивания. OAuth не передаётся на адрес скачивания; переходы по ссылкам ограничены адресами Яндекса, API-перенаправления с OAuth запрещены.

Авторизация: service `Yandex.Disk.MCP`, account `law@vbeton.ru`. Настройка действует на проверенном AirM5. Корень выбранного диска `vd:IuNVVCtUbELgzA:disk:/`, org_id `8117507`; личный `disk:/` отклоняется.

Проверяемый интерфейс: явный выбранный источник и отдельная рабочая папка дают исходные байты, реестр и статус; транспорт Диска заменяется на имитацию только на внешней границе. Это соответствует входам и критериям приёмки поручения. Тесты читают фактические локальные результаты и реестр, не подменяют внутреннюю логику получения.

## Проверки

- 17 новых тестов получения через внешний адаптер и CLI. Проверены вложенность, одинаковые имена, русские пути, 103 файла, пропущенная страница, архив/подпись, безопасные пути, обрывы, повторный запуск, версии, локальная порча, коллизии имён, хеши, ошибки HTTP, Связка ключей и отсутствие пересылки OAuth при скачивании.
- В полном наборе 131 тест, все прошли без пропусков. Системный Python не содержал PDF-зависимостей; для регрессии создана отдельная среда внутри игнорируемого рабочего каталога и установлены существующие зависимости разработки.
- Реальный MCP подтвердил диск «ВБетон», перечислил выбранную служебную папку, вернул метаданные и ссылку безопасного README. Байты получены локальным клиентом чтения API. Это разные проверки; выдача ссылки не засчитывалась как скачивание.
- Безопасный источник: `vd:IuNVVCtUbELgzA:disk:/IT/Distrib/Amnezia/README.md`, 1023 байта, MD5 `8521c036ebdf32d4fc7ca06a0db23be7`. Никакой другой файл из служебной папки не скачивался.
- Повторное получение того же безопасного источника по HTTPS-ссылке на Диск подтвердило поддержку ссылок и повторное использование локального файла с проверкой хешей.
- Полные реестры, безопасный исходник, контрольные суммы восьми задач и резервные копии изменявшихся документов находятся в проектном `work/yandex-disk-integration-20261105/`. В распространяемый навык они не включаются.

Сценарии агента и границы подтверждения описаны в [сценариях](../test-cases/yandex-disk-20261105/scenarios.md). Успех детерминированных тестов не подтверждает качество финансового вывода модели.

## Статус передачи

Реализованы канонические проектные исходники и локальные проверки. Отдельная сборка или выпуск навыка не создавались; установленный снимок общего набора не заменялся. Другие Mac и практическое получение полного пакета выбранного заёмщика не проверялись. Восемь задач локальных расчётов остаются отдельным согласованным набором.
