## Обязательный субагент-аналитик — 19.10.2026

Изменены инструкции оркестрации и стартовый запрос; логика скриптов и макет прежние. Вход — запрос проверки заёмщика с доступными документами; ожидаемый результат — анализ выполнен отдельным субагентом, основной агент возвращает проверенный результат. Критерий успеха — наблюдаемый запуск одного аналитика с доступом к исходникам и завершённый отчёт, а не только сообщение о делегировании.

Проверка по чтению инструкций, без независимого прогона модели:

- Подходящий запрос: «Проверь ООО по отчётности и ОСВ» — основной агент запускает одного аналитика и передаёт исходники; аналитик выполняет шаги 1–5 без повторного делегирования.
- Похожий запрос вне области: «Разбери мой семейный бюджет» — финансовый навык не применяется; правило запуска аналитика не активируется.
- Неполные или противоречивые данные: с 22.10.2026 пробелы в обязательном минимуме останавливают аналитика до расчётов и PDF; ограничения дополнительных данных после допуска отражаются в отдельных показателях.
- Уточнение существующей проверки: дополнительные документы идут прежнему аналитику; новая независимая проверка другого заёмщика получает отдельного.
- Субагенты недоступны: ограничение сообщается явно; анализ основным агентом требует прямого указания пользователя.

Детерминированные тесты расчётов не подтверждают эти маршруты поведения модели. Независимый прогон обновлённой оркестрации ещё не выполнен. Текущий разбор «Архангельского леса» был делегирован до изменения навыка по прямому поручению пользователя и не считается такой проверкой.

Автоматическая проверка выполняется для расчётного результата, каждого поля макета и готового PDF до сохранения. Отдельная команда проверяет PDF, Markdown, текст и JSON.

Всего 40 тестов без пропусков. Новые проверки покрывают падежи и регистр, скрытые Unicode-разделители, JSON с Unicode-экранированием, вложенные строки и источники, страницы PDF, отказ при отсутствии извлекаемого текста и сохранность предыдущего отчёта. Разговорный термин присутствует только в отрицательных тестовых примерах. Исходные документы заёмщика не изменяются. Эти проверки подтверждают терминологический запрет в проверенных результатах, а не общее качество анализа модели.

## Оформление по гайдбуку ВБетон, 20.10.2026

Макет `credit-committee-vbeton-1.1` сохраняет композицию выбранного «Кредитного комитета». Обновлены палитра, гарнитура и верхняя строка с оригинальным векторным логотипом. Верхняя линия опущена для охранного поля. Расчёты, порядок пяти показателей и геометрия аналитических блоков прежние.

Неизменённый гайдбук сохранён в `docs/brand/guidebook-vbeton.pdf`. Контрольная сумма совпала с предоставленным файлом. Происхождение логотипа, настройки и контрольные суммы статических начертаний Roboto Flex записаны в `assets/brand/manifest.json` внутри навыка. Генератор встраивает оба начертания и проверяет ресурсы по SHA-256.

Детерминированные проверки: 41 тест без пропусков. Новый тест сначала завершился ошибкой на прежней палитре, после обновления прошёл. Через готовый PDF он проверяет четыре допустимых RGB-цвета, два встроенных начертания Roboto Flex и векторную форму логотипа. Сохранились проверки координат аналитических блоков на четырёх финансовых сценариях, одностраничности, арифметики, терминологии, воспроизводимости и атомарного отказа при переполнении. Насыщенность 280 и 700 дополнительно проверена по таблице OS/2 статических файлов. Ширина 91 задана при создании начертаний из вариативного исходника, параметры и SHA-256 записаны в манифесте.

Четыре случая заново сформированы в `output/vbeton-brand/qa/` и визуально осмотрены после рендера Poppler: обычный бизнес, риск, неполные данные, посредник. Кириллица и знак рубля читаются, логотип сохраняет пропорции и свободное поле, таблица и сноски помещаются. Образец на вымышленных данных: `output/vbeton-brand/credit-committee-vbeton.pdf`. Это RGB-документ для экрана; CMYK-оригинал для полиграфии не готовился.

Проверка маршрутов инструкций выполнена по чтению, без нового независимого запуска модели:

- Вход «Подготовь заключение по компании». Ожидается чтение правил оформления и рендер закреплённым генератором. Критерий успеха: один лист с фирменной палитрой, встроенным Roboto Flex, векторным логотипом, расчётами и источниками.
- Вход «Сделай рекламный буклет ВБетон». Финансовый навык вне области применения. Критерий успеха: агент не подменяет буклет финансовым заключением.
- Вход с неполной или противоречивой отчётностью. Прежний сценарий макета применяется только после допуска: при пробеле в обязательном минимуме ожидаются остановка и готовый дозапрос, без финансового PDF. Для дополнительных данных после допуска сохраняются доступные расчёты и явные ограничения.
- В гайдбуке встречаются рекламная ставка и пример реквизитов. Ожидается использование только визуальных требований. Критерий успеха: эти сведения не попадают в условия займа или сведения о заёмщике без отдельного источника.

Эти маршруты описывают ожидаемое поведение. Статическое чтение и тесты PDF не подтверждают самостоятельный выбор инструкций моделью.
