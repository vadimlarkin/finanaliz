## Выбранный интерфейс

CLI `python scripts/calculate_loan_schedule.py INPUT.json OUTPUT.json`, публичная функция `calculate(data)`. Код 0 означает рассчитанный график, 2 означает конкретную диагностику с полями входа. Одинаковый вход даёт одинаковый JSON. Источник не изменяется, результат заменяется атомарно. Сеть не используется.

Вход `local-loan-schedule-1.0`: RUB, строковые суммы в рублях, issue_date, amount, term_months, rate с fixed=true и meaning=borrower_nominal_annual_percent, accrual с interest_type=simple, day_count actual_365_fixed/actual_366_fixed/actual_actual, issue_day include/exclude, repayment_day include/exclude. repayments содержит явные даты и суммы основного долга, interest_payment_dates содержит явные даты уплаты процентов. rounding задаёт mode half_up/half_even/down и interest_stage payment/daily. fees является явным массивом комиссий, пустой массив означает подтверждённое отсутствие комиссий. Комиссия имеет id/date и calculation fixed либо percent с явной базой original_principal/outstanding_before_repayment/outstanding_after_repayment. sources содержит проверенные id/file/locator, terms_sources ссылается на договорные условия.

first_12_months задаёт end и include_issue_day/include_end_day для начисления, отдельно cash_include_issue_day/cash_include_end_day для выплат и комиссий. Раздельные флаги уточнены после красного теста комиссии на выдаче, до финализации интерфейса. Никаких значений по умолчанию для границ нет. Конец должен быть первой годовщиной выдачи; для 29 февраля явно допускается выбранное пользователем 28 февраля либо 1 марта следующего года. Для каждого из двух окон ровно одна из граничных дат входит в него. Это исключает скрытое календарное предположение. Начисленные проценты этого окна и выплаты по датам окна сохраняются отдельно. Corporate patch передаёт new_loan_interest_12m по начислению, new_loan_fees_12m по датам комиссий, сумму/ставку/договорный срок; режимы loan_repayment и loan_interest_basis равны schedule. Комиссии не добавляются к процентам patch. Аналитик отдельно подтверждает ставки и источники и объединяет patch с бухгалтерским входом.

Тестируем через CLI и выходной JSON; совместимость через действующий analyze.py. Макеты не меняются. Сценарии поведения агента описываются отдельно от детерминированных тестов, модельные прогоны не заявляются.

2. Тот же долг, погашения 400.00 на 2024-01-06 и 600.00 на 2024-01-11, repayment_day=include. Пять дней на 1000 по 1.00 и пять дней на 600 по 0.60, всего 8.00. При repayment_day=exclude начисление за 2–5 января 4.00 и 6–10 января 3.00, всего 7.00.
3. Високосный календарь: 1000.00, 36.6%, Actual/Actual, 2024-02-28 не входит, 2024-03-01 входит, два дня по 1.00, всего 2.00. Fixed365 даёт 2.005479... и после half_up 2.01.
4. Округление: 1.00, 36.5%, Actual/365, пять дней дают 0.005. Payment half_up даёт 0.01, half_even даёт 0.00, ежедневное half_up даёт пять нулей и итог 0.00.
5. Длинный график: 1000.00, 36.5%, Fixed365, 2025-01-01 не входит, погашение 2026-07-01 входит. 546 дней, 546.00 процентов всего, первые 12 месяцев с исключением выдачи и включением 2026-01-01 дают 365.00 начисленных процентов. Если проценты уплачиваются только в конце, в этом окне уплачено 0.00. Комиссии 10.00 при выдаче и 5.00 на конечную дату: Денежное окно включает выдачу и исключает годовщину, поэтому в нём 10.00 комиссии; итог комиссий всего 15.00. Начисления имеют отдельное окно с исключённой выдачей и включённой годовщиной. Отдельный тест проверяет 20.00 комиссии на выдаче при начисленных процентах 365.00.

Каждый следующий тест добавляется после зелёного предыдущего. Контрольные суммы не вычисляются новым алгоритмом для ожидаемых значений.

## Ограничения и передача

Поддерживаются RUB, простая фиксированная ставка, три явные дневные базы и три режима округления до 0.01 руб. Даты погашений и уплаты процентов уже известны, график не ищется из целевого аннуитетного платежа. Комиссии до выдачи, плавающие ставки, капитализация и неизвестные схемы требуют отдельной поддержки. Программа не подтверждает договорные факты и источник возврата основного долга. Условия и источники должны быть проверены аналитиком до расчёта.
