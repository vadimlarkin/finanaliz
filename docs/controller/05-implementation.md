# Тикет 05. Локальное извлечение PDF

Исходный коммит `e0e6c3a3a473cabf1c178d2dee0966af1e33ce67`. Исполнитель Pdf houdini. Исходный тикет находится в общей папке `.scratch/local-financial-calculations/issues/05-cache-local-pdf-extraction.md`, копия контроллера сохранена без изменения.

## Интерфейс до первого теста

Публичный интерфейс: `extract_pdf_cached.py INPUT --cache-dir DIR [--language rus+eng] [--ocr auto|vision|tesseract|none] [--dpi 200] [--min-text-chars 1] [--output JSON]`.

Наблюдаемый результат: JSON, полный `text.txt` с номерами страниц, SHA256 исходника, параметры и версии инструментов, способ получения и ограничения каждой страницы. Коды завершения 0 для полного извлечения, 2 для неполного результата или ошибки. Полнота означает доступный текст каждой страницы, но не подтверждает правильность OCR или финансовых фактов. Страницы OCR требуют ручной сверки.

Ключ кэша зависит от байтов PDF, существенных параметров, версий инструментов и скриптов. Повторное использование проверяет целостность сохранённых артефактов. Исходник остаётся неизменным. Отдельный JSON может отражать `cache_hit`; содержательный результат в кэше стабилен.

## Независимые контрольные примеры

- Текстовый PDF из двух страниц: строка `SOURCE A 123.45` на странице 1, `SOURCE B 678.90` на странице 2. Обе строки должны появиться со своими номерами без OCR.
- Скан и смешанный PDF: растровая строка `Invoice 123.45 2026-11-05` требует локального OCR. Смешанный документ сохраняет текстовую первую страницу и OCR второй.
- При `--ocr none` скан получает неполный статус и номер страницы, текстовая страница смешанного документа сохраняется.
- Повторный неизменённый вход использует тот же ключ. Замена текста исходного PDF, DPI или минимальной длины изменяет ключ.
- Подмена кэшированного текста обнаруживается; повреждённый кэш не выдаётся как подтверждённый результат.

Тесты CLI и выходных артефактов выполняются последовательно red → green. Проверка качества настоящего OCR выделяется отдельно. Сценарии поведения агента описываются отдельно от тестов скрипта.

## Проверки и результат

Работа велась последовательными CLI-проверками. Красная проверка до реализации показала отсутствие скрипта. Затем отдельно воспроизведены и исправлены отсутствие `cache_hit`, повторное использование повреждённого текста, неверная полнота страницы без OCR, принятие недопустимого DPI, отсутствие настоящего OCR, возможность заменить источник выходным JSON и потеря короткого готового фрагмента при OCR. После каждого изменения соответствующая проверка прошла. Проверки языка и версии Tesseract дополнены через исполняемый адаптер системного инструмента; это не проверка качества Tesseract.

## Исправление после независимой приёмки

Контроллер и Spec inspector воспроизвели P2 на `5e366f7f0a577f2142d3db887bddf690a96331c0`. Скан с готовым номером страницы `1` ошибочно получал `complete: true`, `method: embedded` и пустой список сверки. Причина подтверждена CLI-тестом: единственный символ проходил порог готового текста, наличие растрового содержимого не проверялось. Тест `test_scan_with_embedded_page_number_is_incomplete_without_ocr` сначала вернул 0 вместо ожидаемого 2.

Исправление проверяет структуру страницы, поэтому не зависит от произвольного повышения порога. Любая страница с растровым изображением требует OCR. Без OCR она остаётся неполной, даже если содержит готовый номер, заголовок или длинный текст. Дополнительные поля `raster_images` и `ocr_reason` объясняют обработку. Готовый текст остаётся в `embedded_text`, OCR в `ocr_text`; полный текст явно содержит оба фрагмента, включая возможные повторы. Консервативная цена подхода состоит в дополнительном OCR страниц с растровыми логотипами. Скрипт не отличает логотип от изображения с нераспознанным текстом, ограничение описано в reference.

Добавлены три CLI-проверки: скан с номером без OCR получает код 2; настоящий Vision читает сумму и дату за пределами готового номера; длинный готовый текст с маленьким растровым логотипом также получает понятную причину дополнительной обработки. Целевой набор после исправления: 13 тестов, 7.222 секунды, OK.

Для повторной приёмки сохранены `work/controller-05/scan-page-number.pdf`, `scan-page-number-result.json` и `scan-page-number-no-ocr.json`. Это русский пробный скан с добавленным готовым номером страницы. Режим Vision должен сохранить номер отдельно и распознать `Основной долг 123,45 руб.` и `Дата 05.11.2026`; режим `none` должен оставить результат неполным. `complete` описывает выполненное извлечение по слоям, правильность каждого слова и финансовых фактов по-прежнему проверяет аналитик.
