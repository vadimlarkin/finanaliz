# Импорт CSV-выписки по явному профилю

Прочитай перед импортом табличной выписки в реестр денежных потоков. Подтверди формат банка, счёт, владельца, период и соответствие колонок. Скрипт импортирует один файл одного счёта, проверяет структуру и вызывает действующую арифметику. Произвольные банковские форматы и экономическую классификацию по назначению он не распознаёт.

```sh
python <skill-dir>/scripts/import_statement_csv.py <work-dir>/statement.csv <work-dir>/profile.json <work-dir>/import-result.json --csv-output <work-dir>/prepared.csv
```

Код 0 означает отсутствие ошибок импорта и существующего аудита. Он допускает явно неполный охват и нерешённые категории; проверь `summary.complete`, `summary.unresolved` и ограничения. Код 2 означает ошибку профиля, строки, синтаксиса CSV либо аудита. Подготовленный CSV создаётся только при коде 0. При ошибке прежний CSV сохраняется, JSON диагностики заменяется атомарно. Пути выходов не могут совпадать с исходником, профилем, объявленным источником контроля или друг с другом, в том числе через ссылки.

## Подготовь профиль

Схема `local-statement-csv-1.0`. Пример минимального профиля:

```json
{
  "schema_version": "local-statement-csv-1.0",
  "encoding": "utf-8",
  "delimiter": ";",
  "date_format": "%d.%m.%Y",
  "amount_format": {
    "decimal_separator": ",",
    "group_separator": " ",
    "blank_is_zero": true
  },
  "direction": {
    "mode": "separate",
    "debit_column": "Расход",
    "credit_column": "Приход"
  },
  "columns": {
    "date": "Дата",
    "purpose": "Назначение",
    "currency": "Валюта",
    "category": "Категория"
  },
  "category_map": {
    "Покупатели": {"category": "revenue", "status": "confirmed"},
    "Поставщики": {"category": "suppliers", "status": "confirmed"}
  },
  "currency": "RUB",
  "account": {"account": "A", "owner_id": "OWNER"},
  "period": {"start": "2026-01-01", "end": "2026-02-28"},
  "coverage": {"complete": true},
  "source_id": "STATEMENT",
  "service_rows": []
}
```

Входной профиль сохраняй вместе с результатом. Неизвестные поля, неподдерживаемая схема и противоречащие настройки отклоняются до импорта.

- `encoding` задаёт установленную кодировку, например utf-8, utf-8-sig, cp1251. Для BOM укажи соответствующую кодировку явно. Ошибка декодирования сохраняет SHA256 исходника и диагностику; номера строк недекодированного текста не выдумываются.
- `delimiter` содержит один символ, кроме кавычки и управляющих разделителей строк. Применяются стандартные CSV-кавычки `"` и удвоение кавычек. Первая CSV-запись должна быть заголовком. Предварительные шапки банка требуют отдельной подготовки или будущего подтверждённого профиля.
- `date_format` поддерживает `%d.%m.%Y` и `%Y-%m-%d` с точным числом разрядов. Одна настройка применяется к дате проводки и явно mapped `operation_date`. В реестре даты нормализуются в ISO. Неверная дата имеет физический номер строки.
- `amount_format` задаёт десятичную точку либо запятую и необязательный разделитель тысяч из пробела, неразрывного пробела, точки либо запятой. Разделители различаются. Группы разрядов имеют по три цифры, дробная часть не длиннее двух цифр. Знаки, экспоненты, нечисловые суммы и неподдерживаемый диапазон дают диагностику. Арифметика использует Decimal. `blank_is_zero` явно определяет, означает ли пустая денежная ячейка ноль; неизвестное значение этим правилом подменять нельзя.
- `period`, `coverage` и `account` соответствуют [local-cashflow.md](local-cashflow.md). Даты операций входят в период. Профиль одного счёта не доказывает полноту всех счетов бизнеса. Для разных версий и файлов используй различимые source_id перед объединением источников.
- `currency` должна быть RUB. При mapped колонке валюты каждое значение обязано совпадать с ней. Иную валюту не суммируй с рублями.

## Направление и категории

`direction.mode: separate` использует две разные явно названные колонки. Для формата с меткой направления вместо него задай:

```json
{"mode":"indicator","amount_column":"Amount","indicator_column":"Kind","values":{"D":"debit","C":"credit"}}
```

Неизвестная метка и две ненулевые стороны строки дают ошибку. Назначение, положение чисел в тексте и название дебета/кредита сами по себе направление не определяют. Подтверди значение колонок по формату источника.

`columns` обязательно содержит date и purpose. currency и category необязательны. `category_map` применяется только к явной mapped колонке category и содержит проверенные аналитиком category/status. Поддержанные категории и статусы описаны в [local-cashflow.md](local-cashflow.md). Если отображение отсутствует, операция получает category/status unresolved. Исходная банковская метка сохраняется как source_category. Скрипт не превращает свободный текст назначения в экономическую категорию. Явный основной долг, проценты и комиссии продолжают проходить существующий аудит назначений, который может потребовать исправить категорию перед успехом.

Явно можно сохранить `counterparty_account`, `document_number`, `operation_date`, `bank_operation_id`, `creditor_kind`, `pair_id`, `transfer_confirmation`, указав имя их колонки в columns. Пустые необязательные значения пропускаются. Номер документа не становится bank_operation_id автоматически. Применимость банковского ID, принадлежность кредитора и доказательства переводов проверяет аналитик. Переводы затем обрабатываются по [local-own-transfers.md](local-own-transfers.md).

## Служебные строки и ошибки

`service_rows` содержит точные правила с непустым reason:

```json
[
  {"column":"Назначение","equals":"ИТОГО","reason":"Служебный разделитель выгрузки"},
  {"blank":true,"reason":"Разрешённый пустой разделитель"}
]
```

Правило сравнивает полное значение, без поиска подстроки. Непустая служебная запись должна иметь полное число колонок. Несколько подходящих правил дают ошибку. Пустая строка без явного разрешения, лишняя или пропущенная колонка не игнорируются. Не помечай реальные операции служебными ради устранения расхождения.

`row_results` содержит header, operation, service либо error для каждой записи с `line_start`/`line_end`. Многострочная запись сохраняет диапазон физических строк. При повреждённой кавычке диапазон ошибки охватывает прочитанный остаток, прежний журнал сохраняется. Непригодный заголовок блокирует все строки и имеет отдельную диагностику. При ошибках строки доступный частичный реестр помечен неполным, `summary` и `csv_audit` равны null. Такой набор не является готовым финансовым расчётом.

## Независимая сверка и результат

Независимые значения передай массивом `bank_controls` в профиле по [cashflow-audit.md](cashflow-audit.md). Для каждого контроля нужен source, объявленный в отдельном массиве `control_sources` с id/file/locator. Он должен относиться к счёту и периоду импорта. Пример:

```json
{
  "control_sources":[{"id":"BANK","file":"bank-controls.json","locator":"Итоги выписки"}],
  "bank_controls":[{"account":"A","source":"BANK","opening":"10.00","debit":"20.02","credit":"150.35","closing":"140.33","bank_count":3}]
}
```

Суммы контролей передаются десятичными строками с точкой либо числами, независимо от формата исходного CSV. Их независимость и соответствие оригиналу подтверждает аналитик. Скрипт не извлекает банковский итог из суммы импортированных строк. Пустой массив трактуется как отсутствие контроля. Без него `bank_controls_supplied` равен false и остатки неизвестны. Наличие source не доказывает независимость.

`source` сохраняет путь, SHA256 и размер исходных байтов. `cashflow` принимается расчётом 01, операции имеют устойчивый ID, source/page/source_row и load_id. `loads` содержит ID загрузки, source и тот же SHA256 для дальнейшего сопоставления повторов. Источники контроля сохраняются отдельно, суммы строк остаются в summary. `csv_audit` проверяет назначения и банковскую арифметику. При ошибке аудита подробности доступны в csv_audit.issues и summary.audit.issues, `ok` равен false. Не передавай такой результат генератору.

Воспроизводимые вымышленные два CSV и профили находятся в `examples/local-statement-csv-*` исходного проекта. Они дают поступления 150.35, списания 20.02, изменение 130.33 и закрытие 140.33 при открытии 10.00. Установленный навык не зависит от examples. Повтор неизменного входа даёт одинаковые артефакты; изменение исходника меняет SHA256 и пересчитывает месяцы. Оригинальные файлы не меняются, сеть не используется.

## Сценарии поведения агента

Это проверки инструкции чтением, отдельный модельный прогон не проводился.

- Подходящий запрос: импортировать CSV с известной структурой. Агент подтверждает направление, период и счёт, сохраняет профиль, запускает CLI и проверяет строки, категории и независимый аудит.
- Похожий запрос вне поддержки: автоматически распознать любой банковский формат. Агент получает описание формата либо подтверждённый образец, сохраняет ограничение и не угадывает колонки.
- Неполные данные: нет независимых банковских итогов или проверенных категорий. Агент сохраняет неизвестные остатки и нерешённые суммы, не выдаёт сумму строк за сверку банка.
- Противоречие: неверная дата, короткая строка или несходящиеся обороты банка. Агент сверяет конкретную строку/период с оригиналом, исправляет подготовку и повторяет импорт; не удаляет операцию ради равенства итогов.
