# Локальное извлечение PDF с повторным использованием

Применяй к исходным PDF до финансового разбора. Скрипт сохраняет текст и его происхождение, экономические категории и факты проверяет аналитик.

```sh
python3 scripts/extract_pdf_cached.py /path/source.pdf \
  --cache-dir /path/work/pdf-cache --language rus+eng --ocr auto \
  --output /path/work/extraction.json
```

Нужен `pypdf` из зависимостей навыка. Для OCR нужен локальный `pdftoppm` и один распознаватель: Tesseract либо Apple Vision через Swift на macOS. В режиме `auto` сначала проверяется Tesseract, затем Vision. Сетевых запросов и загрузки языков скрипт не выполняет. Если подходящий инструмент или нужный язык отсутствует, страницы без готового текста перечисляются как неполные. Для русско-английского документа указывай `rus+eng`. Vision сопоставляет их с `ru-RU+en-US`; другие языки задаются кодами выбранного движка.

Сначала скрипт извлекает готовый текст через pypdf для каждой страницы. На странице без растровых изображений пригодность текста определяется параметром `--min-text-chars`, минимальным числом букв и цифр, по умолчанию 1. Этот технический порог не определяет правильность слов и полноту таблиц.

Страница с растровым изображением консервативно требует OCR независимо от длины готового текста. Наличие готового номера страницы, заголовка или даже большого фрагмента не доказывает, что текст внутри изображения уже извлечён. Скрипт не умеет достоверно отличать скан документа от логотипа и готовый слой OCR от неполного текстового слоя. Поэтому страницы с растровыми логотипами тоже получают дополнительное OCR. Если OCR недоступно или выключено, такие страницы получают `unavailable`, `complete: false` и требуют ручной сверки; готовый текст при этом сохраняется.

Для каждой страницы `raster_images` сообщает число найденных растровых изображений, `ocr_reason` объясняет выбор OCR. Значение `raster_content` означает наличие изображения, `insufficient_embedded_text` означает отсутствие пригодного готового текста. Готовые и распознанные фрагменты сохраняются отдельно и соединяются в полном тексте с маркером `[OCR]`. Дублирование одинаковых фрагментов в обоих слоях сохраняется явно, автоматического смыслового слияния нет. Смешанный документ содержит все страницы по порядку. Sidecar не используется как замена полному тексту.

`--dpi` задаёт разрешение OCR от 72 до 600, по умолчанию 200. `--ocr none` извлекает только готовый текст. `vision` и `tesseract` требуют именно указанный движок. `--output` задаёт отдельный JSON, исходный PDF этим аргументом заменять нельзя.

## Результат

В каталоге `<cache-dir>/<cache_key>/` находятся:

- `result.json` со SHA256 исходника, параметрами, версиями pypdf, распознавателя, рендерера, ОС для Vision и контрольными суммами скриптов;
- `text.txt` с полным текстом по порядку и маркерами `=== Page N ===`;
- `manifest.json` с контрольными суммами обоих артефактов для проверки целостности кэша.

Для каждой страницы сохранены `page`, `text`, `embedded_text`, `ocr_text`, `method`, `errors`, `review_required`, `minimum_confidence`. Короткий готовый фрагмент, не прошедший порог пригодности, сохраняется в `embedded_text` и в полном тексте перед маркером `[OCR]`. Распознанный текст отдельно доступен в `ocr_text`. Метод равен `embedded`, `ocr` или `unavailable`. Для Tesseract общий уровень уверенности не вычисляется, поле содержит `null`. `source.path` и номер страницы позволяют открыть исходник для сверки; `source.sha256` связывает результат с его байтами. Все страницы OCR входят в `review_pages`, даже если текст выглядит уверенно.

`complete: true` означает, что для каждой страницы получен готовый текст, а при растровом содержимом выполнено OCR с непустым пригодным результатом. Это полнота выполненного извлечения по выбранным слоям, она не подтверждает распознавание каждого слова, финансовые факты или точность OCR. При `complete: false` прочитай ошибки каждой страницы и сверяй её по оригиналу. Пустая страница тоже может требовать такой проверки. Полностью непригодный или защищённый PDF даёт общую ошибку. Коды завершения: 0 при полном извлечении, 2 при неполном результате или ошибке.

## Повторный запуск

Ключ учитывает байты исходника, язык, режим OCR, DPI, порог пригодности, версии и контрольные суммы инструментов обработки. Неповреждённый кэш повторно используется без извлечения страниц и OCR; `cache_hit` становится `true`. Доступность и версии локальных инструментов проверяются до поиска кэша. Изменение источника, параметров или инструмента создаёт другой ключ. Изменение содержимого артефакта без соответствующей контрольной суммы вызывает повторное извлечение. Неполный результат также сохраняется; появление ранее отсутствовавшего инструмента меняет ключ. Для принудительного повторного извлечения используй новый каталог кэша или удали только запись нужного ключа.

Исходник скрипт открывает для чтения. Рендерер получает временную копию. Кэш и извлечённый текст могут содержать частные данные, размещай их в рабочем каталоге дела вне Git. Суммы, даты, реквизиты и связи строк со столбцами сверяй с оригиналом. Алгоритм не восстанавливает структуру таблиц и не подтверждает классификацию операций.

## Сценарии поведения агента

Эти сценарии проверяют инструкцию отдельно от тестов скрипта. Автоматический запуск сценариев модели не выполнялся.

| Запрос | Ожидаемое действие |
| --- | --- |
| Извлечь текст русско-английской выписки | Указать `rus+eng`, получить все страницы, сверить значимые суммы и даты по оригиналу. |
| По извлечённому тексту автоматически подтвердить платёж | Сохранить происхождение, проверить платёж по исходнику и другим данным; факт платежа не выводится из успешного OCR. |
| PDF частично не читается, распознаватель отсутствует | Использовать доступный текст с оговоркой, назвать номера неполных страниц и конкретный недоступный инструмент. |
| Продолжить по изменённому PDF | Запустить с теми же явными параметрами, получить новый ключ; прежний результат не подставлять к новым байтам. |
