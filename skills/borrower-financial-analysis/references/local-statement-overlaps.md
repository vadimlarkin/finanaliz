# Повторные и перекрывающиеся банковские выгрузки

Используй перед расчётом по нескольким выгрузкам, которые могут содержать повторные представления платежа. Сначала подготовь проверенные операции по [local-cashflow.md](local-cashflow.md) и сведения о версиях исходников.

```sh
python <skill-dir>/scripts/reconcile_statement_overlaps.py <work-dir>/overlap-input.json <work-dir>/overlap-result.json
```

Код 0 означает, что совпадения разрешены и пересчёт прошёл существующий аудит. Код 2 означает ошибку структуры, неразрешённое совпадение, неприменимое решение либо ошибку расчётного аудита. Скрипт не обращается к сети и не изменяет входной JSON или исходные выгрузки. Результат записывается атомарно в отдельный файл. Путь и жёсткая ссылка на вход не могут служить выходом.

## Подготовь вход

Схема `local-statement-overlaps-1.0` содержит:

- `cashflow`: исходный реестр `local-cashflow-1.0`, включая период, счета и владельцев, источники, категории, охват и независимые банковские контроли при наличии. Контроли относятся к выбранному периоду и уникальным банковским операциям. Расчётные суммы строк не заменяют их.
- `loads`: массив уникальных `id`, объявленного `source` и `sha256` исходника из 64 строчных hex-символов. Один source обозначает одну версию. Повторно загруженный неизменный файл может иметь другой load ID и source ID при прежнем SHA256. Фактический хеш файла и правильность подготовки строк проверяет аналитик или предыдущий импорт; этот скрипт получает уже подготовленные сведения и не подтверждает их вместо него.
- `decisions`: необязательный массив ранее принятых решений.

Каждая операция дополнена `load_id` и `source_row`. Загрузка должна ссылаться на тот же source, что и операция. source_row является точным устойчивым локатором одной строки операции в неизменном исходнике. Одного номера страницы с несколькими платежами недостаточно. Поле page сохраняет обычный номер страницы или строки для ручной сверки.

Необязательный `bank_operation_id` означает проверенный уникальный идентификатор банковской операции в рамках счёта. Его смысл должен быть подтверждён форматом банка или аналитиком. Номер платёжного документа, дата и сумма сами по себе таким идентификатором не считаются. Пустое поле следует опустить. Иные дополнительные поля операции сохраняются, включая сведения о собственных переводах и основаниях их подтверждения.

Локальные ID разных операций уникальны. Повтор того же ID допускается только для неизменной строки того же исходника. Так повторное добавление выгрузки с прежними ID не удваивает операции. Переиспользованный ID при изменённых данных вызывает конкретную ошибку; исправь идентификаторы по происхождению, сохраняя связь представлений.

В исходном проекте есть вымышленный пример `examples/local-statement-overlaps.json`. Две загрузки ссылаются на одинаковые байты включённого `examples/local-statement-overlaps-source.csv`, SHA256 рассчитан по этому файлу. Итог составляет 100.10 руб., одна учитываемая операция.

## Проверь совпадения

Повтор автоматически подтверждается по неизменному SHA256 и source_row либо по account и проверенному bank_operation_id. Даты, суммы, стороны, валюта, назначение, категории и дополнительные значимые поля должны согласовываться. Формат даты и десятичной записи нормализуется, остальные различия сохраняются для сверки. Встречные реквизиты и противоречащие банковские ID не игнорируются.

Совпадение только счёта, даты, суммы, направления и назначения становится кандидатом. Обе строки сохраняются до решения. Разные проверенные банковские ID подтверждают два реальных платежа, даже если их дата, сумма и назначение одинаковы. Источники и технические локаторы не служат экономической классификацией.

`confirmed_duplicates` содержит сохранённый ID, повторное представление и основание. `candidates` и `unresolved_matches` перечисляют текущие неразрешённые пары; `identity_conflict` раскрывает differing_fields. Неразрешённая существенная пара означает `clean: false`; готовый summary отсутствует. Оба представления остаются в реестре.

## Сохрани решение аналитика

Решение относится к двум разным известным ID:

```json
{
  "ids": ["EXPORT-A-ROW-2", "EXPORT-B-ROW-5"],
  "action": "duplicate",
  "keep_id": "EXPORT-A-ROW-2",
  "reason": "Один банковский платёж, сумма выбранной редакции сверена по оригиналу",
  "fingerprints": {
    "EXPORT-A-ROW-2": "<SHA256 из operation_fingerprints>",
    "EXPORT-B-ROW-5": "<SHA256 из operation_fingerprints>"
  }
}
```

Действие duplicate сохраняет выбранную редакцию keep_id и все ссылки на представления. Действие distinct сохраняет два реальных платежа и не содержит keep_id. Основание непустое; при необходимости укажи в нём файл и реквизит, по которым проверена связь. Скрипт сохраняет решение и его основание, но не доказывает достоверность утверждения аналитика.

fingerprints содержат снимки обеих операций из результата предыдущего запуска, включая дополнительные значимые поля, загрузку, версию источника, его описание и счёт с владельцем. Изменение такого снимка даёт stale_decision. Решение не применяется и требует повторной сверки. Добавление новой независимой выписки не отменяет решения по прежним неизменным строкам. Неприменимое решение не игнорируется молча.

Транзитивные связи учитываются: duplicate A/B и duplicate A/C с одним keep_id разрешают повтор B/C; distinct одной пары разных групп распространяется на их подтверждённые представления. Различение внутри уже объединённой группы, повтор решения пары и разные выбранные keep_id одной группы требуют диагностики. Для группы с несколькими редакциями выбери единую сохраняемую редакцию и укажи её в разрешающих duplicate-решениях. При конфликте решений очистка блокируется, все исходные логические строки остаются, ручные решения не объявляются применёнными. Неизменные повторные представления одного локального ID продолжают учитываться один раз.

## Пересчитай и продолжи

`registry` содержит подготовленный реестр для CLI 01. У каждой сохранённой операции statement_appearances раскрывает все source, load_id, source_row, page, исходные ID и SHA256. Эти сведения сохраняются в operations результата calculate_cashflow.py. Отдельный lineage позволяет сверить ту же связь без поиска по строкам. raw_operations, loads, decisions и operation_fingerprints сохраняют исходные данные и версии для продолжения.

Для добавления выписки используй исходные raw_operations, исходный охват и прежние решения, затем добавь новые строки, источники и загрузки. Не используй уже сокращённый registry вместо полного исходного набора. Пересчёт выполняется заново публичной функцией calculate_cashflow.calculate. Общие и месячные суммы, число уникальных операций и банковские сверки не накапливаются из прежних итогов.

`summary` доступен только при разрешённых совпадениях. Его ok и pdf_compatible по-прежнему зависят от существующего банковского и категорийного аудита. clean означает только разрешённость совпадений, полноту бизнеса и независимый банковский контроль это поле не подтверждает.

При ошибке решений или нерешённых парах `provisional_summary` показывает арифметику сохранённых представлений для сверки. Она может включать два представления одного платежа. Это не подтверждённый денежный поток. В ней ok, complete и pdf_compatible равны false, pdf_patch равен null. registry имеет неполный охват. Не передавай такой результат генератору PDF. После исправления исходных данных или решений повтори тот же CLI; одинаковый вход даёт одинаковые байты результата.

## Сценарии поведения агента

Это проверка инструкции чтением, отдельный модельный прогон не проводился.

- Подходящий запрос: «Добавь февральскую выписку, январь в ней повторяется». Агент сохраняет версии источников, запускает сопоставление, сверяет подтверждённые повторы и месяцы, затем использует готовый summary после успешного аудита.
- Похожий запрос вне области: «Удаляй все одинаковые суммы в один день». Агент сохраняет реальные платежи, запрашивает признаки идентичности и основания. Слабого совпадения недостаточно для удаления.
- Неполные данные: две одинаковые строки без банковского ID. Агент показывает кандидата, получает duplicate или distinct с основанием и актуальными снимками. До этого не выдаёт provisional_summary за полный результат.
- Противоречие: у одного банковского ID различаются сумма или встречные реквизиты. Агент сверяет оригиналы, исправляет подготовленные данные либо явно выбирает подтверждённую редакцию. Прежнее решение с изменённым снимком повторно не применяется.
