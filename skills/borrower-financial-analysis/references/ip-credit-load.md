# Расчёт кредитной нагрузки на срок займа

Прочитай при подготовке формы ИП. Расчёт описывает выплаты другим кредиторам за период рассматриваемого займа. Остаток долга и источник денег на выплату проверяются отдельно. Основа для долговой части: прямые активные обязательства самого ИП из представленного БКИ с сохранением УИд, дат записей и страниц.

## Подготовь период и обязательства

1. Возьми число месяцев из `loan.term_months`. Начальный месяц равен известному плановому месяцу выдачи. Если он не установлен, используй месяц анализа как расчётное допущение. Явно выбранный пользователем период имеет приоритет. Зафиксируй основание начала в `credit_load`; не переноси даты прошлого заёмщика. Последний расчётный месяц равен начальному плюс срок минус один.
2. Составь одну запись на каждый УИд обязательства. Включай известные среднемесячные показатели БКИ в `monthly_payment`. Точный известный регулярный платёж допускается при документально установленной периодичности. Минимальный платёж карты не объявляй полным обслуживанием без основания. Сохрани дату расчёта показателя и ссылку на первичную страницу. Исторические суммы выплат из выписок не заменяют будущую месячную нагрузку.
3. В `payments` передай известные отдельные платежи с датами и источниками. Если этот платёж уже входит в месячную базу того же договора, используй `replace`: все такие платежи месяца вместе заменяют его базу. Если он действительно уплачивается сверх базы, используй `additional`. Для обязательства без регулярного показателя передай `monthly_payment: null`, а известный платёж как отдельный. Не дублируй один УИд под именами разных банков или один платёж с разными идентификаторами.
4. По умолчанию известная месячная база повторяется в каждом расчётном периоде. `monthly_until` допустим только для последнего месяца подтверждённых регулярных выплат. Общая дата окончания договора, дата окончания уплаты процентов, беспроцентного периода карты или техническое значение `31.12.9999` сами по себе не задают такой месяц. Наступивший срок не доказывает фактическое погашение. После него нужны сведения об исполнении для вывода о закрытии.
5. Недоступный платёж оставляй неизвестным. Ноль требует прямого подтверждения. Отсутствие суммы финального платежа овердрафта не превращает её в ноль. В расчёт включаются только имеющиеся компоненты; неизвестный охват и допущения сохраняются в аудите. Ни итог, ни календарь не устанавливают право кредитора на конкретный эскроу. Будущий основной долг не выводится вычитанием всех платежей, включающих проценты, из текущего остатка.

Критерий готовности: период соответствует текущему займу; обязательства и платежи не дублируются; каждый показатель имеет источник; для точных сумм месяца выбран способ учёта относительно базы; неизвестные компоненты сохранены в рабочих данных.

## Контракт `credit_load`

Вход `ip-investor-3.1`, поле `credit_load`:

```json
{
  "start_month": "2026-12",
  "start_basis": "planned_disbursement",
  "start_sources": ["LOAN"],
  "contracts": [
    {
      "id": "UID-A",
      "monthly_payment": {
        "value": 1000,
        "status": "confirmed",
        "sources": ["BKI"],
        "as_of": "2026-10-20"
      },
      "payments": [
        {
          "id": "UID-A-PAYMENT-1",
          "date": "2026-12-15",
          "treatment": "replace",
          "amount": {"value": 1200, "status": "confirmed", "sources": ["BKI"]}
        }
      ]
    }
  ]
}
```

Суммы в рублях. Факты используют общий формат `value` / `status` / `sources`, для вычисленных фактов нужен `derivation`. Идентификаторы источников должны присутствовать в корневом `sources`. `monthly_until`, если установлен, имеет формат `YYYY-MM`. `payments` можно опустить, `monthly_payment` оставить `null`. УИд обязательств и идентификаторы платежей уникальны. `treatment` обязателен, допустимы только `replace` и `additional`.

`start_basis`: `assessment_month`, `planned_disbursement` или `user_scenario`. Для двух последних обязательны `start_month` и `start_sources`. При отсутствии начала используется месяц `assessment_date` с основанием `assessment_month`. Срок от 1 до 1200 целых месяцев. При неизвестном сроке расчётный период и итог остаются неизвестными; независимые финансовые факты продолжают выводиться.

## Расчёт и форма

`render_ip_dashboard.py` вызывает расчёт и сохраняет его в `credit_load` аудита вместе с PDF. Для каждого месяца сначала берётся база каждого договора, затем применяются замены и дополнительные платежи этого договора, после чего значения складываются. Расчёт ведётся в рублях и копейках с Decimal. Отдельные платежи вне выбранного периода сохраняются в аудите, но в итог периода не включаются. Новый рассматриваемый заём в этот блок не входит.

В аудите доступны `period`, `period_months`, `start_basis`, `start_sources`, `regular_monthly_rub`, `regular_contracts`, `total_rub`, `months`, `contracts`, `status` и `calendar`. `status: partial` означает известный итог доступных компонентов при наличии неизвестных платежей. Пустой набор даёт `missing` и `null`, а не ноль. При неизвестных значениях всего месяца его сумма остаётся `null`.

PDF воспроизводит согласованный блок:

- Заголовок «Расчёт кредитной нагрузки до [месяца и года]» по концу периода.
- Строка «Расчётный сценарий: [N] месяцев с [месяца и года] по [месяц и год].» с правильными окончаниями. После точки дополнительных пояснений нет.
- Две карточки «Регулярно по [N] договорам» и «Всего за [N] месяцев».
- «Календарный план погашения», голубая строка периодов и суммы в млн ₽.

Ноябрьская или другая отдельная карточка пикового месяца, примечания под календарём и фраза про «наш возврат» в PDF не выводятся. Источники, состав отдельных платежей и ограничения остаются в аудите. При недоступных данных соответствующее значение отображается как «Нет данных», в календаре как «н/д».

До 12 месяцев календарь помесячный. Для 13–36 месяцев PDF показывает последовательные периоды по три месяца, далее периоды по 12 месяцев; при сроке свыше 144 месяцев размер периода увеличивается кратно году так, чтобы осталось не более 12 колонок. На странице явно указаны размер периода и точные месяцы его границ. Аудит всегда сохраняет все месяцы без группировки. Итог PDF равен сумме исходных месячных значений.
