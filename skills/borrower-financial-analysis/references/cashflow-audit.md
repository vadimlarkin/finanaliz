# Проверка подготовленного CSV денежных потоков

`check_cashflow.py` проверяет подготовленные операции. Он читает CSV и необязательный JSON независимых банковских итогов, печатает JSON проверки, возвращает 0 при отсутствии обнаруженных ошибок и 2 при ошибке. Исходные файлы не меняются. Это аудит явных назначений и арифметики, не распознавание PDF и не автоматическое подтверждение всех экономических категорий.

```bash
python <skill-dir>/scripts/check_cashflow.py <work-dir>/transactions.csv --bank-controls <work-dir>/bank-controls.json
```

Сохрани stdout в отдельный рабочий файл, например cashflow-audit.json. Этот JSON не является корпоративным analysis.json. При отсутствии независимых банковских итогов проверка указывает bank_controls_supplied=false; её успех не означает банковской сверки. Перед выпуском полного числового разбора используй контроли либо явно раскрой несверенный охват.

## Вход

UTF-8 CSV с обязательными столбцами `id,source,page,account,date,debit,credit,purpose,category`. ID уникален, источник и страница/строка заполнены, дата ISO или ДД.ММ.ГГГГ. Суммы неотрицательны, десятичная точка, не больше двух знаков; одна сторона операции ненулевая. Валюта RUB по умолчанию; другая валюта требует отдельного расчёта и сюда не суммируется. Дополнительные столбцы сохраняются в источнике и не удаляются проверкой.

Для встречных переводов нужны `pair_id` и `counterparty_account`. В каждой паре две операции, одинаковые сумма и дата, встречные счета, разные исходные счета. Каждая сторона учитывается один раз. Из оборота исключаются только подтверждённые пары. Остаток после их исключения не называется полным внешним оборотом: там могут остаться собственные переводы за пределы охвата.

JSON контролей является массивом объектов `account,opening,debit,credit,closing`, необязательно `bank_count` и `currency`. Контрольные суммы внеси из итогов банка независимо от извлечённых строк; вычисление обоих наборов одним способом не даёт независимой сверки. Нулевые счета могут быть в контролях без строк операций.

Для проверяемых типов принимаются следующие категории:

| Смысл | Русское значение | Допустимое короткое значение |
| --- | --- | --- |
| Проценты | проценты по долгу | interest |
| Пени/штрафы | пени по долгу | penalty |
| Комиссия | комиссии и банковское обслуживание | fee |
| Основной долг | погашение основного долга | principal |
| Встречный собственный перевод | собственный перевод между представленными счетами | own_transfer_matched |

Для прочих категорий разрешены содержательные названия, включая неопределённый состав возврата. Проверка не доказывает их экономическую корректность. Возвраты процентов и комиссий остаются в кредитовой стороне соответствующей категории; они не уменьшают фактические выплаты в дебете автоматически.

## Что проверяется отдельно

- Обязательные поля, суммы, даты, уникальность ID.
- Явные формулировки процентов с разными глаголами, пени/штрафы, комиссии и явно названный основной долг. Приоритет санкций сохраняется для пеней за просроченные проценты.
- Название договора «займ с процентами» само по себе не делает весь возврат процентами.
- Обе стороны каждой пары переводов.
- Обороты, остатки и число операций против независимых банковских итогов.

В JSON отражены ошибки с ID операции/источником, раздельные дебет и кредит по категориям и итогам, число операций, банковских счетов и проверенных пар. Успех этой проверки дополняется чтением существенных операций по оригиналам. Неоднозначные назначения, полнота расходов, достоверность документов, доступность денег и будущая платёжеспособность остаются предметом анализа.
