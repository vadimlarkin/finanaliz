# Финансовый анализ — разработка скилла

Работай и общайся с пользователем по-русски. Этот проект предназначен для разработки скилла для ИИ-агента. Содержание финансового анализа уточняй по исходникам проекта и текущей задаче.

## Обязательная терминология

Используй только термин **«основной долг»** в нужном падеже для суммы займа без процентов и комиссий. Соблюдай правило в ответах, отчётах, инструкциях, формулах, шаблонах, примерах и поручениях субагентам. Перед передачей созданного текста, JSON или PDF выполняй `skills/borrower-financial-analysis/scripts/check_terminology.py`; при ошибке исправь формулировку и повтори проверку. Оригинальные документы сохраняй без изменений; в своём изложении используй канонический термин. Определение — в `GLOSSARY.md`.

## Agent skills

Навыки Matt Pocock подключены как локальные файлы в `vendor/mattpocock/skills/`. Это подключение через инструкции проекта; автоматическая регистрация в каталоге Codex не настроена, поскольку `.agents/skills` защищён от записи в текущей среде.

Перед применением навыка прочитай его `SKILL.md`, затем только необходимые связанные материалы. Если инструмента Skill нет, используй чтение файла. Разрешай имена других навыков по таблице ниже. Не загружай весь набор за один раз.

### Issue tracker

Задачи и спецификации — локальные Markdown-файлы. Перед `to-spec`, `to-tickets` и `code-review` прочитай `docs/agents/issue-tracker.md`.

### Domain docs

Единый контекст: `GLOSSARY.md` и `docs/adr/`. Перед работой с терминами прочитай `docs/agents/domain.md` и существующие документы по теме.

## Разработка и проверка скилла

Оформляй финансовые отчёты по гайдбуку ВБетон. Текущий макет и правила применения гайдбука находятся в `skills/borrower-financial-analysis/references/report-layout.md` и `references/vbeton-brand.md` внутри того же навыка. При изменении дизайна обновляй генератор, версию макета, образец и проверки вместе.

Разрабатываемый скилл размещай отдельно от инструментов разработки: `skills/<skill-name>/SKILL.md`, с ресурсами в `scripts/`, `references/`, `assets/` по необходимости. Инструменты из `vendor/` не включай в распространяемый скилл.

Для каждого изменения поведения определи вход, ожидаемый результат и наблюдаемый критерий успеха. Проверяй инструкции на конкретных примерах запросов: подходящий запрос, похожий запрос вне области применения, неполные или противоречивые данные. Проверки поведения модели и детерминированные тесты скриптов описывай отдельно; прохождение статических проверок не доказывает качество ответов модели.

Для расчётов используй скрипты и независимо проверенные контрольные примеры. Финансовые суммы и выводы связывай с источниками; отсутствующие данные явно отмечай. Вспомогательные скрипты проверяй через наблюдаемый результат, применяя `tdd` при изменении логики. Простые правки текста проверяй чтением и подходящими сценариями.

Оригинальные файлы Matt Pocock сохраняй без изменений; проектные настройки храни здесь и в `docs/agents/`. Источник, версия и контрольные суммы находятся в `vendor/mattpocock/manifest.json`. При обновлении сверяй зависимости и связанные файлы, затем проверяй настройки проекта.
