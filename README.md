# Финансы заёмщика

Навык для ИИ-агента: предварительно разобрать финансовое состояние компании перед выдачей займа и получить **один лист A4 по фиксированному макету «Кредитный комитет»**.

Для частных кредиторов. Обычный бизнес и финансовые посредники; российские компании и российская отчётность. Автор: Вадим Ларкин.

[Фиксированный макет](skills/borrower-financial-analysis/references/report-layout.md) · [Методика](skills/borrower-financial-analysis/references/methodology.md)


## Установка из GitHub

Установите навык в своего ИИ-агента через [Skills CLI](https://github.com/vercel-labs/skills):

```bash
npx skills add vadimlarkin/finanaliz --skill borrower-financial-analysis
```

Установщик предложит выбрать поддерживаемого агента. По умолчанию установка выполняется в текущий проект; `-g` устанавливает навык для всех проектов. Например, для Codex:

```bash
npx skills add vadimlarkin/finanaliz --skill borrower-financial-analysis -a codex
```

Для Skills CLI нужен Node.js 22.20+. Поддерживаются Codex, Claude Code и другие агенты, перечисленные в документации установщика. Сам анализ требует чтения файлов и запуска Python 3.9+ с `reportlab` и `pypdf`; кириллические шрифты включены.

Можно поручить установку своему агенту: «Установи навык borrower-financial-analysis из https://github.com/vadimlarkin/finanaliz».

## Использование

После установки откройте новую сессию агента и вызовите навык. Для Codex:

```text
$borrower-financial-analysis
Проверь потенциального заёмщика по документам в <путь-к-документам>.
Условия займа: <сумма>, <ставка>, <срок>, <порядок выплат>.
Подготовь один лист PDF по фиксированному макету «Кредитный комитет».
```

Начать можно с баланса и отчёта о финансовых результатах. ОДДС, пояснения, ОСВ, договоры, графики и выписки расширяют проверку. Нужны документы одного заёмщика. Если условия займа ещё неизвестны, навык покажет доступные показатели и ограничения. Дату проверки укажите, если нужна не текущая.

Каждую новую проверку навык поручает отдельному субагенту-аналитику. Основной агент координирует работу и возвращает готовый отчёт; уточнения продолжаются у того же аналитика. Если агентная среда не поддерживает субагентов, навык сообщает об ограничении; анализ в основном контексте возможен по прямому указанию пользователя.

Обновления устанавливаются командой `npx skills update borrower-financial-analysis`.

## Что показывает лист

| Показатель | Вопрос кредитора |
| --- | --- |
| Покрытие процентов | Хватает ли заработка на стоимость заёмных денег? |
| Долговая нагрузка | Как соотносятся процентный долг и собственный капитал? |
| Деньги на 90 дней | Хватает ли средств по платёжному плану на ближайшие выплаты? |
| Денежное покрытие | Покрывал ли исторический поток долговые выплаты? |
| После нового займа | Как изменится процентное покрытие при дополнительном долге? |

Отдельно показывается чувствительность к снижению прибыли, обычно на 20%. Это условный сценарий, а не прогноз. Отсутствующие данные и неприменимость шкалы явно подписываются в таблице. Финансовый посредник анализируется с поправкой на фондирование и денежное движение портфеля; коэффициент долг/капитал у него не получает универсальную цветовую оценку.

Цвета — авторские ориентиры предварительной проверки, а не нормативы, рейтинг или вероятность дефолта. Итог не является разрешением выдать заём. Источник возврата основного долга проверяется отдельно.

Макет и правила заполнения закреплены в [report-layout.md](skills/borrower-financial-analysis/references/report-layout.md). Агент заполняет данные; оформление создаёт только поставляемый генератор.

## Воспроизводимые расчёты

Модель извлекает факты из документов и указывает источники; Python проверяет структуру, периоды, календарные даты, числа и вычисляет показатели. Рендер заново считает их из исходного JSON. Содержание и достоверность источников всё равно нужно проверять по оригиналам.

```bash
python -m pip install -r skills/borrower-financial-analysis/scripts/requirements.txt
python skills/borrower-financial-analysis/scripts/analyze.py examples/operating.json work/analysis.json
python skills/borrower-financial-analysis/scripts/render_dashboard.py examples/operating.json work/dashboard.pdf --audit-json work/analysis.json
```

Python 3.9+. Шрифты Liberation Sans включены и проверяются по SHA-256. Координаты, размеры, цвета и порядок полей фиксированы в генераторе. Одинаковый вход даёт одинаковые PDF-байты в одной среде. При переполнении рендер выдаёт ошибку, а не обрезает факты и не добавляет вторую страницу.

## Ручное подключение

Скопируйте каталог `skills/borrower-financial-analysis` в поддерживаемый вашим агентом каталог навыков. Например, для проекта Codex:

```bash
mkdir -p .agents/skills
cp -R skills/borrower-financial-analysis .agents/skills/
```

Либо укажите агенту путь к `SKILL.md` прямо в запросе. Инструменты разработки Matt Pocock в `vendor/` не нужны для использования финансового навыка. Для разработки смотрите `AGENTS.md`.

## Терминология

Для суммы займа без процентов и комиссий используется **основной долг**. Расчётный скрипт и генератор отклоняют неканонические разговорные обозначения. Отдельная проверка PDF, Markdown, текста и JSON:

```bash
python skills/borrower-financial-analysis/scripts/check_terminology.py work/dashboard.pdf work/analysis.json
```

Правило закреплено в `AGENTS.md`, `GLOSSARY.md` и инструкциях навыка.

## Проверки и ограничения

Четыре вымышленных случая: обычный бизнес, нехватка средств, неполный пакет, финансовый посредник. Автоматические проверки и независимый запуск навыка описаны в [docs/validation.md](docs/validation.md).

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Все демонстрационные компании и документы вымышлены. Ни один пример не является результатом проверки реального заёмщика. Автоматический расчёт не заменяет проверку извлечённых из PDF/сканов цифр.

## Данные и лицензии

Скрипты не выполняют сетевых запросов. При загрузке документов в ИИ-сервис действуют условия выбранного сервиса; отсутствие сетевого кода в скриптах не означает локальную обработку всего чата.

Реальные документы заёмщиков, банковские выписки и результаты проверок держите вне публичного репозитория. Каталоги `private/`, `work/`, `input/`, `borrower-documents/`, `reports/` исключены из Git; перед публикацией проверяйте состав файлов.
