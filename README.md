# Финансы заёмщика

Генератор `investor-one-page-2.2` включает [согласованные изменения одностраничного отчёта](skills/borrower-financial-analysis/references/approved-report.md). Исходный принятый PDF, текущий образец, превью и воспроизводимый вход включены в проект. Установка навыка на устройства выполняется отдельно от изменения исходников.

Навык для ИИ-агента: предварительно разобрать финансовое состояние компании перед выдачей займа и получить **один лист A4 по фиксированному макету «Кредитный комитет» в оформлении ВБетон**.

Для частных кредиторов. Обычный бизнес и финансовые посредники; российские компании и российская отчётность. Автор: Вадим Ларкин.

[Фиксированный макет](skills/borrower-financial-analysis/references/report-layout.md) · [Оформление ВБетон](skills/borrower-financial-analysis/references/vbeton-brand.md) · [Методика](skills/borrower-financial-analysis/references/methodology.md)


## Установка из GitHub

Установите навык в своего ИИ-агента через [Skills CLI](https://github.com/vercel-labs/skills):

```bash
npx skills add vadimlarkin/finanaliz --skill borrower-financial-analysis
```

Установщик предложит выбрать поддерживаемого агента. По умолчанию установка выполняется в текущий проект; `-g` устанавливает навык для всех проектов. Например, для Codex:

```bash
npx skills add vadimlarkin/finanaliz --skill borrower-financial-analysis -a codex
```

Для Skills CLI нужен Node.js 22.20+. Поддерживаются Codex, Claude Code и другие агенты, перечисленные в документации установщика. Сам анализ требует чтения файлов и запуска Python 3.9+ с `reportlab` и `pypdf`; кириллические шрифты включены.

Можно поручить установку своему агенту: «Установи навык borrower-financial-analysis из https://github.com/vadimlarkin/finanaliz».

## Использование

После установки откройте новую сессию агента и вызовите навык. Для Codex:

```text
$borrower-financial-analysis
Проверь потенциального заёмщика по документам в <путь-к-документам>.
Условия займа: <сумма>, <ставка>, <срок>, <порядок выплат>.
Подготовь один лист PDF по фиксированному макету «Кредитный комитет».
```

Сначала навык проверяет обязательный минимум по [правилам приёма документов](skills/borrower-financial-analysis/references/intake.md): компанию и ИНН, модель бизнеса, условия нового займа, годовые баланс и ОФР, общую ОСВ за истекший период года, сведения о действующих кредитах и займах, выписки по всем расчётным счетам за полный год. Период выписок составляет 12 полных месяцев по конец последнего завершённого месяца.

При неполном или непригодном минимуме навык останавливается до расчётов и создания PDF. Вы получите перечень пробелов и готовое сообщение заёмщику, несогласованные условия нашей сделки уточняются у кредитора отдельно. Полный минимум позволяет продолжить анализ, даже если для отдельных показателей нужны дополнительные документы. Дату проверки укажите, если нужна не текущая.

Каждую новую проверку навык поручает отдельному субагенту-аналитику. Основной агент координирует работу и возвращает готовый отчёт; уточнения продолжаются у того же аналитика. Если агентная среда не поддерживает субагентов, навык сообщает об ограничении; анализ в основном контексте возможен по прямому указанию пользователя.

Обновления устанавливаются командой `npx skills update borrower-financial-analysis`.

## Что показывает лист

| Показатель | Вопрос кредитора |
| --- | --- |
| Прибыль от продаж / проценты | Как соотносятся прибыль и проценты до и после займа? |
| Процентный долг / капитал | Как изменится соотношение долга и капитала после займа? |
| Банковские, небанковские без связанных, связанные займы | Сколько основного долга есть сейчас, без рассматриваемого нового займа? |

Прибыль и начисленные проценты для первой строки берутся за последние 12 месяцев по последнюю доступную дату финансовых результатов, с точным периодом под строкой. После займа добавляются проценты нового займа за первые 12 месяцев. Если подтверждённого полного периода нет, показывается «Нет данных» без подстановки старого года или пропорционального пересчёта неполного периода.

На листе также показываются таблица финансового состояния за два предыдущих года и текущий период и диаграмма выручки, ЧКО, погашения основного долга и процентов за общий период текущего года. Диаграмма занимает левую половину, текущий основной долг правую; два соотношения с колонками «До займа» и «После займа» находятся ниже. «Деньги на 90 дней», «Денежное покрытие» и стресс остаются только в служебном JSON. В PDF есть сноски по ОСВ и исключению нового займа из текущих сумм. Отсутствие и неприменимость расчёта различаются. У финансового посредника первая строка называется «Заработок до фондирования / проценты».

В PDF используется фирменная палитра ВБетон. Уровень риска раскрывается текстом; цвет не означает норматив, рейтинг или вероятность дефолта. Итог не является разрешением выдать заём. Источник возврата основного долга проверяется отдельно.

Макет и правила заполнения закреплены в [report-layout.md](skills/borrower-financial-analysis/references/report-layout.md). Агент заполняет данные; оформление создаёт только поставляемый генератор.

## Воспроизводимые расчёты

Модель извлекает факты из документов и указывает источники; Python проверяет структуру, периоды, календарные даты, числа и вычисляет показатели. Рендер заново считает их из исходного JSON. Содержание и достоверность источников всё равно нужно проверять по оригиналам.

```bash
python -m pip install -r skills/borrower-financial-analysis/scripts/requirements.txt
python skills/borrower-financial-analysis/scripts/analyze.py examples/investor.json work/analysis.json
python skills/borrower-financial-analysis/scripts/render_dashboard.py examples/investor.json work/dashboard.pdf --audit-json work/analysis.json
```

Python 3.9+. Фирменные начертания Roboto Flex и векторный логотип ВБетон включены и проверяются по SHA-256. Координаты, размеры, цвета и порядок полей фиксированы в генераторе. Одинаковый вход даёт одинаковые PDF-байты в одной среде. При переполнении рендер выдаёт ошибку, а не обрезает факты и не добавляет вторую страницу.

## Ручное подключение

Скопируйте каталог `skills/borrower-financial-analysis` в поддерживаемый вашим агентом каталог навыков. Например, для проекта Codex:

```bash
mkdir -p .agents/skills
cp -R skills/borrower-financial-analysis .agents/skills/
```

Либо укажите агенту путь к `SKILL.md` прямо в запросе. Инструменты разработки Matt Pocock в `vendor/` не нужны для использования финансового навыка. Для разработки смотрите `AGENTS.md`.

## Терминология

Для суммы займа без процентов и комиссий используется **основной долг**. Расчётный скрипт и генератор отклоняют неканонические разговорные обозначения. Отдельная проверка PDF, Markdown, текста и JSON:

```bash
python skills/borrower-financial-analysis/scripts/check_terminology.py work/dashboard.pdf work/analysis.json
```

Правило закреплено в `AGENTS.md`, `GLOSSARY.md` и инструкциях навыка.

## Проверки и ограничения

Четыре вымышленных случая: обычный бизнес, нехватка средств, неполный пакет, финансовый посредник. Автоматические проверки и независимый запуск навыка описаны в [docs/validation.md](docs/validation.md).

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Все демонстрационные компании и документы вымышлены. Ни один пример не является результатом проверки реального заёмщика. Автоматический расчёт не заменяет проверку извлечённых из PDF/сканов цифр.

## Данные и лицензии

Скрипты не выполняют сетевых запросов. При загрузке документов в ИИ-сервис действуют условия выбранного сервиса; отсутствие сетевого кода в скриптах не означает локальную обработку всего чата.

Реальные документы заёмщиков, банковские выписки и результаты проверок держите вне публичного репозитория. Каталоги `private/`, `work/`, `input/`, `borrower-documents/`, `reports/` исключены из Git; перед публикацией проверяйте состав файлов.
